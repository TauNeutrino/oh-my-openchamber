# Kein Goal-Modus in der Ausführung

Der Agent kann sich kein Goal auf seine eigene laufende Session setzen; OpenChamber erlaubt Goals nur beim Anlegen einer Session. Ein „Goal-bewaffnetes Kind" oder eine „Fortsetzungs-Session" wäre ein Plattform-Workaround, der als Architektur verkleidet worden wäre — abgelehnt.

Entschieden: Die Ausführung läuft **ohne Goal-Modus**. Der Dirigent arbeitet in seiner eigenen Session den kanonischen WorkOrder ab; die Wachhalt-Disziplin ist die Continuation-Regel im Prompt (jeder neue Input führt zurück zum offenen Auftrag), nicht eine Server-Schleife. Der Nutzer kann ein Goal jederzeit selbst bewaffnen, wenn er volle Autonomie will — dann ist es sein Werkzeug, kein Architekturteil.

Konsequenzen: Keine zweite Session-Rolle, keine Doppelsteuerung, kein Budget-Mechanismus im Modell. Der Test für Autonomie verlagert sich auf die Qualität des WorkOrder und der Protokolle.
